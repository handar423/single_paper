\section{Additional Generality Results}
\label{app:generality}

We evaluate generality along three deployment dimensions: cluster resource
distribution, function-set size, and function-popularity distribution. We report
CPU utilization and task throughput as representative metrics of resource
efficiency and system performance, respectively. Unless otherwise stated,
improvements at 100\% offered load are relative to the best-performing baseline
for each metric. Because Golgi and Golgi-NoCC exhibit only minor performance
differences, we report only Golgi in these experiments.

\textbf{Resource distributions.}
Figures~\ref{fig:gen_simple} and~\ref{fig:gen_zipf} compare performance under
uniform and Zipf-distributed resource availability. The uniform setting exposes
75\% of each server's capacity, whereas the Zipf setting uses eight resource
tiers with $\alpha=0.8$. Across both settings, COSMOS follows the same overall
trend as in the main experiment: its advantage becomes pronounced as load
approaches capacity and persists under overload. At 100\% load, COSMOS improves
CPU utilization by 37.63\% and 43.04\%, and throughput by 87.30\% and 90.10\%,
under the uniform and Zipf settings, respectively. This consistency shows that
complementary swarming remains effective when resource availability is either
balanced or highly heterogeneous.

\textbf{Number of functions.}
Beyond the default ten-function setting, we evaluate two additional function-set
sizes:

\begin{itemize}
    \item \textbf{Five functions}: video-processing, graph-pagerank,
    image-recognition, dna-visualisation, and thumbnailer. We double each
    function's invocation rate to maintain a comparable aggregate load.

    \item \textbf{Twenty functions}: the original ten functions plus one replica
    of each. A replica has the same code, resource profile, and runtime as its
    original but is treated as a distinct function, preventing instance reuse
    between the pair. We halve each function's invocation rate to preserve the
    aggregate user traffic.
\end{itemize}

Figures~\ref{fig:gen_func5} and~\ref{fig:gen_func20} show that COSMOS's advantage
grows with workload diversity. At 100\% load, COSMOS improves CPU utilization by
19.15\% and 42.73\%, and throughput by 70.44\% and 94.97\%, with five and twenty
functions, respectively. With fewer functions, each node already serves a
relatively small function set, leaving less room to improve locality. As the
function set grows, complementary swarming more effectively limits the distinct
functions handled by each node and increases instance reuse.

\textbf{Workload distributions.}
Finally, we compare the default workload with an 80/20 popularity skew while
preserving the aggregate invocation rate. In the skewed setting, thumbnailer and
video-processing collectively account for 80\% of invocations.
Figures~\ref{fig:gen_workload_default} and~\ref{fig:gen_skewed} show that COSMOS
consistently outperforms the baselines, although its margin is smaller under the
skewed workload. At 100\% load, COSMOS improves CPU utilization by 37.34\% and
throughput by 99.56\% under the default workload; under the 80/20 workload, the
corresponding gains are 18.31\% and 18.00\%. Concentrating most requests on two
functions naturally increases their reuse opportunities even for the baselines,
reducing the optimization headroom for complementary swarming. Nevertheless,
COSMOS retains an advantage under highly skewed function popularity.

\section{Larger-scale Cluster Experiment}
\label{app:large-cluster}

We further evaluate COSMOS on a 16-worker CloudLab cluster, twice the default
cluster size. We proportionally scale the invocation frequency while keeping
all other experimental conditions unchanged. Figure~\ref{fig:eval_big} compares
COSMOS with the baselines across offered loads. As in the eight-worker cluster,
COSMOS's advantage becomes more pronounced as the offered load approaches
cluster capacity and remains under overload. At 100\% load, COSMOS improves CPU
utilization, memory utilization, and task throughput over the best-performing
baseline by 35.78\%, 39.40\%, and 67.43\%, respectively. The consistent trend
shows that COSMOS retains its performance advantage as the cluster scales from
eight to sixteen workers.
